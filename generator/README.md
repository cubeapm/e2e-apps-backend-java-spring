# Unified CubeAPM data generator

One Docker stack, driven by **one config file** (`config.yaml`), that fills a
CubeAPM instance with **continuous, multi-tenant, multi-vendor** telemetry.

Where the per-vendor branches (`otel`, `datadog`, `newrelic`, `elastic`) each run
*one* app, *one* vendor, *one* org and need you to curl endpoints by hand, this
runs them **all together** and generates traffic on its own — each workload
carrying its own **service name** and **`x-cube-org-slug`** (tenant).

```
                          ┌────────────────────────────────────────────┐
 config.yaml  ──generate──▶ docker-compose.generated.yml + nginx + json │
                          └────────────────────────────────────────────┘
                                            │ docker compose up
        ┌───────────────────────────────────┼───────────────────────────────────┐
        ▼                                    ▼                                   ▼
  real Spring apps (1 JVM each)        tenant-gateway (nginx)             synthetic (curl)
  otel / datadog / elastic / nr        injects x-cube-org-slug            OTLP/JSON traces+logs
        │  ▲                            per org for DD/Elastic/NR          sets header itself
        │  └── loadgen (curl loop, continuous traffic) ──┘                       │
        ▼                                    ▼                                   ▼
                                  ┌──────────────────────┐
                                  │       CubeAPM        │  (org routing via x-cube-org-slug)
                                  └──────────────────────┘
```

## Prerequisites

1. **Docker** (Desktop on macOS). Nothing else — the generator runs in a container.
2. A running **CubeAPM** reachable at `host.docker.internal` on the ingest ports
   (`4318` OTLP HTTP, `3130` ingest). Adjust in `config.yaml › cubeapm` if different.
3. **Pre-create the org slugs** you use in `config.yaml` (`acme`, `globex`,
   `initech` by default) in CubeAPM. An **unknown slug silently falls back to the
   default org** — so if everything shows up under "default", your slugs don't
   exist yet.

## Usage

```bash
cd generator
make up        # generate + build + start everything (detached)
make logs      # follow logs
make ps        # container status
make down      # stop (keeps mysql data);  make clean = also drop the volume
```

Edit `config.yaml`, then `make up` again (it regenerates first).

## The config

| Key | Meaning |
|-----|---------|
| `cubeapm.host / otlp_http_port / ingest_port` | where telemetry is sent |
| `cubeapm.newrelic.enabled` | `false` skips all New Relic services |
| `cubeapm.newrelic.upstream_port` | CubeAPM port that accepts New Relic intake |
| `defaults.environment / service_version` | stamped as resource attributes |
| `defaults.traffic.rps / error_ratio` | per-service load (overridable per service) |
| `services[]` | real app containers: `name`, `vendor`, `org_slug`, optional `traffic` |
| `synthetic[]` | lightweight OTLP streams: `service_name`, `org_slug`, `rps`, `signals` |

`vendor` is one of `otel`, `datadog`, `elastic`, `newrelic`. "N services × M orgs"
= N×M app containers (one JVM each), so keep the real `services[]` list modest and
lean on `synthetic[]` for breadth.

## How multi-tenancy works per vendor

The tenant header is **`x-cube-org-slug`** (honored uniformly by CubeAPM across
OTLP/Datadog/New Relic/Elastic). But only some agents can set it themselves:

| Vendor | How the slug is attached | Multi-org |
|--------|--------------------------|-----------|
| **OTEL** | native `OTEL_EXPORTER_OTLP_HEADERS` — sends direct to CubeAPM | ✅ direct |
| **Synthetic** | curl sets the header per request — direct to CubeAPM | ✅ direct |
| **Datadog** | tracer → **tenant-gateway** (nginx adds header) → CubeAPM `:3130` | ✅ via gateway |
| **Elastic** | agent → **tenant-gateway** → CubeAPM `:3130` | ✅ via gateway |
| **New Relic** | agent (TLS) → **tenant-gateway** (TLS, header) → CubeAPM | ⚠️ via gateway, see below |

The **tenant-gateway** is a tiny nginx with one listener per org; each listener
injects that org's `x-cube-org-slug` and forwards to CubeAPM. It exists only
because the Datadog/Elastic/New Relic agents can't add a per-request header.

### New Relic caveat

New Relic's Java agent always speaks **TLS** and offers no custom-header knob, so
its traffic goes through the gateway's per-org **TLS** listener (self-signed cert,
generated by `make certs`; the agent trusts it via `NEW_RELIC_CA_BUNDLE_PATH`).
Two things to verify against your CubeAPM:

- **`cubeapm.newrelic.upstream_port`** — the port CubeAPM accepts New Relic intake
  on (default `3130`).
- **Collector redirect** — the NR agent may follow a `redirect_host` returned by
  the backend during connect; if CubeAPM returns a host other than the gateway,
  the per-org header could be bypassed. If New Relic data won't appear or lands in
  the wrong org, either point New Relic at your real TLS CubeAPM endpoint, or set
  `cubeapm.newrelic.enabled: false` to drop it. The other three vendors are
  unaffected.

### Datadog note

Datadog runs **agentless** (traces only) via `DD_TRACE_AGENT_URL` → gateway. To
add Datadog logs/metrics you'd reintroduce a `datadog-agent` sidecar per org (see
the `datadog` branch) — out of scope for v1.

## What `make up` generates (git-ignored)

- `docker-compose.generated.yml` — the full stack
- `nginx/nginx.conf` — the per-org gateway
- `loadgen/targets.json`, `synthetic/streams.json` — runtime inputs
- `certs/` — self-signed gateway cert

## Verify

1. CubeAPM up; org slugs pre-created.
2. `make up`, wait ~1–2 min for the JVMs to boot and the loadgen warmup.
3. In the CubeAPM UI, switch orgs and confirm each shows only its own services
   (`acme` → checkout-otel, payments-dd, recommendations; `globex` →
   inventory-elastic, shipping-nr; `initech` → search-otel, notifications), with
   traces (incl. DB/cache/error spans), metrics and logs flowing continuously.
4. Negative check: set a service's `org_slug` to something not in CubeAPM →
   it appears under **default**, proving the pre-create requirement.
